Issue 2 (Critical)

Worker currently executes bucket-level copy.

I see references such as:

Shell
rclone copy gcs:$B azure:$B

during migration.

For delta workers, avoid repeatedly scanning entire buckets.

Recommended:

Plain Text
Batch
|
batchfile.txt
|
rclone --files-from batchfile.txt

Much more scalable.

Issue 3 (Critical)

No stale batch recovery.

Current:

SQL
PROCESSING

can remain forever if a worker dies.

Add recovery cron.

Example:

SQL
UPDATE sync_batches
SET status='PENDING'
WHERE status='PROCESSING'
AND created_at < NOW() - INTERVAL '30 minutes';

Without this, one crashed worker can leave batches stranded.

Issue 4 (Critical)

No PostgreSQL backup section.

I would add.

Daily backup:

Shell
pg_dump gcssync \
> /backup/gcssync_$(date +%F).sql

Retention:

Plain Text
30 Days

The runbook currently lacks PostgreSQL recovery procedures.

No WAL/Vacuum maintenance.

With millions of events:

SQL

batch_files
blob_events

Add:

SQL
